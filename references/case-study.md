# 案例研究：monetize-skill 的 README 重写（2026-10-31）

> 星数与校准样本采样于 2026-10-31（案例发生日），仅供说明流派差距，不用于精确排序；2026-11-09 复核时头部仓库星数已变化。竞品格局见 references/competitors.md。

本技能方法论的首个真实案例。仓库：zhengqiuyang/monetize-skill（单技能仓库，Agent Skills 生态）。提交：`da4b18f`。

## 背景

仓库已有手写双语 README（约 60 行，纯文字），内容准确但"个人配置感"重。目标：开源发布级门面。

## 第 0 步的校准过程（复盘）

拉了同生态两个头部仓库的 README 头部做实拆：

| 样本 | ⭐ | 观察到的流派特征 |
|---|---|---|
| obra/superpowers | 309,833 | **极简排版派**：零徽章零图，H1 + 一段话价值主张 + 目录 + 按工具分流的安装段（14+ 个工具各一节）+ How it works 叙事。高级感全靠信息架构和文案语气 |
| VoltAgent/awesome-agent-skills | 36,669 | **全组件派**：居中 banner（`<picture>` 明暗自适应）+ 徽章墙（awesome.re、星数、更新时间、Discord）+ 赞助商表格 |

判断：目标仓库是**单技能仓库**，不是列表也不是框架 → 中间路线（徽章排 + mermaid + 原生警告框），不上 banner。理由：banner 是列表/框架仓库的配置，单技能仓库用了会显得用力过猛；而完全零徽章的极简派需要 30 万星的底气才立得住。

## 做了什么

1. **居中 hero + 显式锚点**：标题下双语价值主张各一行 → 5 枚徽章（MIT / Agent Skills 规范 / SKILL.md 格式 / 星数 / 更新时间，全部 flat-square）→ `npx skills add` 安装命令直接进 hero → 底部导航链接指向显式 `<a id>` 锚点
2. **mermaid 流程图**：6 模块漏斗 + 方向确认检查点（菱形决策节点），7 节点内
3. **原生警告框分工**：NOTE=安装提示，TIP=真实运行凭证的亮点介绍，WARNING=免责声明（框内放 `##` 标题省版面）
4. **before/after 对照表**："一次性提示词 vs 结构化工作流" 5 行对比——比小标题罗列更有说服力
5. **`<details>` 折叠**：报告结构全文折叠进组件，不撑长页面

## 刻意没做什么（同等重要）

| 跳过项 | 理由 |
|---|---|
| banner 大图 | 单技能仓库 + 无设计资产；上了反而用力过猛 |
| 赞助商表格 / Discord 徽章 | 实体不存在，放了就是空壳，违反诚实红线 |
| TOC | README 不到 200 行，hero 顶部导航已够用 |
| 明暗自适应图 | 无设计资产可放 |

## 结果与验证

- 重写后 README 约 100 行（+100/-38），信息密度显著提升
- 用户主观评价："提升很大，非常不错"（作者自评，仅作记录，不作为效果证据；对外展示应换成第三方仓库或可复核指标）
- 渲染检查由用户在 GitHub 页面完成（mermaid/徽章/警告框只有渲染后才算数）

## 可复用的元教训

1. **校准先于动手**：如果不看 superpowers 和 VoltAgent 的真实样本，就会按想象堆组件
2. **克制清单和选型清单同等重要**：用户问"能不能加 X"时，答案经常是"你的仓库类型不配得上它"——这不是贬损，是档位判断
3. **诚实红线不是道德说教而是实用规则**：空壳组件（假徽章/占位截图）一眼即穿，比没有组件更减分
4. **锚点必须显式**：中文标题的自动锚点在导航链接里会裂

# 案例研究 #2：WattWatch（2026-10-31，同日）

仓库：zhengqiuyang/WattWatch（私有，C# WinForms Windows 功耗监控托盘工具，v0.1.0，无 Release）。PR #1 + 后续修补提交。

## 校准样本（Windows 桌面/托盘工具生态）

| 样本 | ⭐ | 规律 |
|---|---|---|
| TrafficMonitor | 46,750 | 徽章排 + 下载链接前置 + 顶部语言切换 |
| EarTrumpet | 11,507 | 徽章排 + hero GIF 立即出现 |
| LibreHardwareMonitor | 9,306 | 徽章排 + "Where can I download it?" 提前 |

类目规律：**截图与下载入口是第一卖点**（工具类仓库靠视觉与可用性卖）。档位：中间路线。

## 事实审计的实战价值（本次最亮部分）

- 核实 7 项技术断言全部通过（csproj/源码 grep 逐条对照）
- 抓到 1 处数字错误（测试数 25 → 实数 27）
- 揪出 3 个真问题：死链截图（引用不存在的 docs/screenshot.png）、无 LICENSE、无 Release
- 处置：死链改 HTML 注释占位（诚实红线：不放假图位）；LICENSE 交用户决定后补 MIT；无 Release 用 NOTE 警告框如实说明"从源码构建"，不装作有下载入口

## 克制决策

动态徽章（星数/更新时间）**没加**——私有仓库 shields.io 拉不到数据，徽章会裂图。规则：组件不仅要指向真实实体，还要在当前仓库可见性状态下能正常渲染。

## 首跑翻车与自纠（写给未来维护者）

首跑把导航写成中文标题自动锚点（`[功能](#功能)`），**违反了本技能自己的显式锚点规则**——验收步骤（第 4 步）复查时发现，合并后追加修正提交。教训：验收检查清单不是形式，写技能的人自己也会漏；**每次跑完必须真走一遍第 4 步**。

2026-11-09 补记：这类问题现由 `scripts/check_readme.py` 的 **R004** 在提交前静态拦截——把踩过的坑固化成 gate，而不是只写进复盘。

## 附加价值

事实审计副产品：发现仓库无 topics → 顺手补齐 8 个（windows/csharp/dotnet/power-monitor/energy-monitor/electricity/tray-application/carbon）；无 LICENSE → 补 MIT。打磨 README 的过程天然暴露仓库级的元数据缺口。

# 案例研究 #3：clipbrain（2026-10-31，同日第三跑）

仓库：zhengqiuyang/clipbrain（公开，Electron 剪贴板管理器，MIT，9 个 topics 齐全，有 CI）。PR #1 已合并。

## 本次检验的是"克制"：内容已经很好时，技能该做什么

事实审计 24 用例、快捷键、轮询间隔、混合权重、CI 矩阵、smoke 脚本——**全部属实，零事实错误**（三个案例中唯一）。内容漏斗完整、诚实声明章节自成一体、ASCII 面板图和架构图都是作者深思熟虑的风格选择。此时正确的产出是**小手术**（+99/-73 两文件）而不是重构。

## 抓到的两个结构性缺陷

1. **"双语对"名存实亡**：README.md 自称 English 但正文是中文；README.zh-CN.md 的 "English" 链接又指回那个中文文件。两文件同 commit 生成但按不同语言标题各自漂移（51 行 diff）。
2. **License 徽章裂图**：`[![License: MIT](https://github.com/.../blob/main/LICENSE)](LICENSE)` ——图片 src 直接指向 LICENSE 文件页面而非 shields.io，GitHub 上渲染为裂图（对应 gate 的 **R002**）。

## 处置：把承诺变成真，而不是拆掉承诺

- README.md 写成**真英文版**（忠实翻译已核实内容，含面板图和架构图的标签翻译）→ 切换链接变成真话
- README.zh-CN.md 定为全中文正统版（以事实核查过的内容为准，恢复中文标题）
- 修复徽章、居中 hero、显式锚点导航、flat-square 统一

## 克制决策（同样重要）

- ASCII 面板图/架构图**保留不转 mermaid**——它是有效风格且已在工作
- 诚实声明章节**保持原样不转警告框**——它是仓库的身份特征，转换反而抹掉个性
- 不放假截图占位——ASCII 模型图已经诚实地扮演了截图角色
- 不加安装提示警告框——Quick start 已足够醒目

## 三案例对照（技能的收益模式）

| 案例 | 事实审计 | 结构发现 | 产出规模 |
|---|---|---|---|
| monetize-skill | 内容全新手写 | — | 全重写（100 行） |
| WattWatch | 1 处数字错误 + 死链截图 + 缺 LICENSE/topics | 下载入口应前置 | 结构重构 |
| clipbrain | **零错误** | 假双语对 + 裂图徽章 | 小手术 |

结论：技能价值不在"把 README 变长变花"，而在**校准档位 + 揪出说谎的结构 + 只在内容配得上时加组件**。内容越好的仓库，产出越小——这是特性不是失败。

2026-11-09 补记：三个案例暴露的机械问题（死链截图、中文自动锚点、裂图徽章）分别对应 gate 的 **R001 / R004 / R002**。方法论文档负责判断，`scripts/check_readme.py` 负责兜底；两者缺一，验收就还是靠人记性。
